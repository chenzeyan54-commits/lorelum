本页供能够执行本地命令的 Agent 使用。当工程指导有助于用户任务时，使用 Lorelum 从已安装 Knowledge Pack 中检索 Practice。可以直接向 Agent 提供本页的 [Markdown 版本](./agents.md)。

## 配置环境

在命令环境中检查 `lore --version`。若不可用，按[安装](./installation)准备 CLI，并保留完整发行目录。

检查已安装 CLI 和 Pack：

```sh
lore describe
lore pack list --details
```

用户需要的 Pack 缺失时安装它。官方工程 Pack 的安装命令是：

```sh
lore pack install agentic-coding@0.3.0
```

按[接入 Agent](./agent-setup)配置当前宿主。Codex 使用[官方 Plugin](./codex)。围绕当前仓库执行一次查询并读取完整 Practice，验证配置。

若使用自定义 `--store-root`，install、query、get 和 index 命令应保持一致。它选择 Pack 和索引数据，不选择其他模型或 Backend。

## 在需要工程判断时检索

适合检索的时刻包括确定范围、划分实现边界、选择验证、恢复上下文，以及准备宣布完成。

说明具体任务和当前时刻：

```sh
lore query "我正在实现账户设置，局部组件测试已通过，准备判断整个功能是否已经完成。"
```

不要将 Pack 目录当作完整指导，也不要假定它穷尽所有相关知识。查询应服务于当前判断，无需在每条命令前机械检索。

## 读取并应用

根据结果中的 `title` 和 `appliesWhen` 选择候选，然后读取全文：

```sh
lore get <practice-id>
```

使用 query 或 Pack 列表返回的精确 `practiceId`。结合当前代码和用户要求检查适用条件。Practice 辅助工程判断，不会授权新增任务范围，也不能替代完成证据。

新事实改变判断时，再次检索。说明相关指导如何影响工作，不要声称应用了未读取或不相关的 Practice。

## 处理 JSON 和退出状态

stdout 包含一个 JSON 响应，stderr 包含诊断和进度。先检查 `ok`，再检查 `data` 中该命令的具体字段。

| 结果 | 后续动作 |
| --- | --- |
| query 可用，包含 `data.results` | 选择相关结果，用 `get` 读取。 |
| `ok: true`、`data.state: "preparing"`、退出码 `1` | 检查模型状态，用 `lore model load` 等待，再重试原查询。 |
| query 可用，但 `results` 数组为空 | 检查已安装 Pack，必要时补充更具体的任务描述。 |
| index 返回已接受的 operation | 根据 operation ID 检查，直到完成或失败。 |
| `ok: false`、退出码 `2` | 检查 `error.code`，按[故障排查](./troubleshooting)处理。 |

默认使用 semantic query。语义查询失败不代表没有相关指导。仅在明确需要离线查询或隔离语义运行时问题时使用 keyword 模式，并明确说明检索模式。

## 查询已安装版本的合同

```sh
lore describe query
lore describe get
lore describe index.build
```

通过这些 schema 查询参数、字段、错误和退出码，不要假定当前版本与其他版本相同。更多内容见 [CLI 参考](./cli)和[文档概述](./index.md)。
